# PandaDOS v2.4.1

## Highlights / 版本亮点

- **English:** Issue identifiers are now collaboration-safe strings that combine the creation date, a random component, and a machine component, while existing numeric identifiers remain valid.<br>
  **中文：**Issue 标识现在采用适合团队协作的字符串格式，组合创建日期、随机段和机器段，同时继续兼容已有数字标识。
- **English:** Project file paths shown in conversations and Issue execution messages can open the corresponding file or preview directly in the workspace.<br>
  **中文：**对话与 Issue 执行消息中显示的项目文件路径，现在可以直接在工作区打开对应文件或预览。
- **English:** Local agents can use the installed PandaDOS Issue inbox skill to discover, inspect, and acknowledge newly created Issues.<br>
  **中文：**本地 Agent 现在可以通过已安装的 PandaDOS Issue 收件箱技能发现、查看并确认新建的 Issue。

## New Features / 新功能

- **English:** Cross-instance project synchronization preserves the new Issue identifier and resolves identifier collisions without changing existing numeric records unnecessarily.<br>
  **中文：**跨实例项目同步会保留新的 Issue 标识，并能处理标识冲突，同时避免不必要地改动现有数字记录。
- **English:** The Issue inbox skill supports project listing, new-Issue queries, Issue details, and acknowledgement cursors through the existing authenticated API.<br>
  **中文：**Issue 收件箱技能通过现有鉴权 API 支持项目列表、新 Issue 查询、Issue 详情及确认游标。
- **English:** New, imported, and existing projects now share the Issue-board workflow, while project conversations remain available as a separate capability.<br>
  **中文：**新建、导入和已有项目现在统一使用 Issue 看板工作流，项目对话仍作为独立能力保留。

## Improvements / 改进

- **English:** The skill policy editor now provides search, policy filters, inherited-state indicators, bulk reset, clearer unsaved changes, and responsive controls.<br>
  **中文：**技能策略编辑器新增搜索、策略筛选、继承状态提示、批量恢复、清晰的未保存状态和响应式控件。
- **English:** Issue ordering, routes, protocol markers, module records, subscriptions, usage data, and design links now consistently support both legacy numeric IDs and the new string IDs.<br>
  **中文：**Issue 排序、路由、协议标记、模块记录、订阅、用量数据和设计关联现在统一支持旧数字 ID 与新字符串 ID。
- **English:** Paused work is represented consistently in boards and summaries, and unresolved input submission remains visible instead of being retried indefinitely.<br>
  **中文：**暂停任务现在会在看板和摘要中保持一致展示；无法确认的输入提交会保持可见，而不会无限重试。

## Fixes / 修复

- **English:** A newly started Issue now takes ownership of the active conversation after preceding work pauses or becomes blocked, preventing an Issue from appearing active without a running agent session.<br>
  **中文：**前一项工作暂停或阻塞后，新启动的 Issue 会接管当前活动对话，避免出现状态已运行但没有 Agent 会话的假运行。
- **English:** Input submission detection now handles delayed rendering, narrow terminals, folded paste content, and Codex running indicators while limiting fallback Enter presses to one confirmed attempt.<br>
  **中文：**输入提交检测现在可处理延迟渲染、窄终端、折叠粘贴内容和 Codex 运行标识，并将兜底 Enter 严格限制为一次受控尝试。
- **English:** Multiline `NEED_PLAN` responses are recognized correctly, preventing automatic execution from stalling when the reason appears on the following line.<br>
  **中文：**系统现在可以正确识别多行 `NEED_PLAN` 响应，避免原因位于下一行时自动执行停滞。

## Upgrade Notes / 升级说明

- **English:** This release migrates Issue identifiers and their references to text. Stop active work and back up the database and runtime data before upgrading.<br>
  **中文：**本版本会把 Issue 标识及其引用迁移为文本类型。升级前请停止正在执行的工作，并备份数据库与运行数据。
- **English:** After updating, run `bun install --frozen-lockfile`, `bun run check-i18n`, `bun run typecheck`, `bun test`, and `bun run build-ui`, then restart the service and verify `/healthz`.<br>
  **中文：**更新后请依次运行 `bun install --frozen-lockfile`、`bun run check-i18n`、`bun run typecheck`、`bun test` 和 `bun run build-ui`，随后重启服务并检查 `/healthz`。
