<h2 id="cn-v2.6.7">新增功能</h2>

- 在暂停或受阻的 Issue 中打开独立故障对话，查看当前轮次的证据和诊断，并由用户提交恢复请求。
- 在确认成果已合入、执行已停止后，归档并校验候选工作区中的诊断和运行数据，再回收候选目录。

## 体验优化

- 故障弹窗保留对话、诊断和处理进度。重新打开可以继续查看，确认解决后可从已有执行阶段恢复。
- 空闲模块可释放被忽略的依赖、构建产物和缓存。后续任务在原工作区按锁文件重新准备依赖。

## 问题修复

- 自动提交排除运行会话、临时状态和根依赖目录。解除旧运行文件的 Git 跟踪时保留本地内容和历史。

## 其他变更

- 新增工作区回收账本和故障会话记录，支持重启后对账。执行机空间不足时延后启动新工作，可固定需要长期保留的归档。

<h2 id="en-v2.6.7">New Features</h2>

- Open a separate incident conversation from a paused or blocked issue, review evidence for the current attempt, and submit a recovery request manually.
- Archive and verify diagnostics and runtime data before reclaiming a candidate workspace once its changes are integrated and execution has stopped.

## Improvements

- The incident dialog retains the conversation, diagnosis, and progress. Reopen it to continue reviewing the incident, then confirm resolution to resume from the existing execution stage.
- Idle modules can release ignored dependencies, build outputs, and caches. Later tasks reinstall locked dependencies in the existing workspace.

## Bug Fixes

- Exclude runtime sessions, temporary state, and root dependencies from automatic commits. Untracking older runtime files preserves local contents and Git history.

## Chores

- Persist workspace reclamation and incident records for reconciliation after restarts. Defer new work when executor space is low and allow archives to be pinned for retention.
