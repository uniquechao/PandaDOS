<h3 id="cn-v2.6.0">新增功能</h3>

- 不同模块可在独立 Git worktree 中并行执行，同模块任务保持串行，并按项目并发上限调度。
- issue 和对话支持选择模型与推理强度，区分已选择、等待切换和会话已确认生效的配置。
- 空闲聊天会话支持自动休眠，默认 2 小时、可配置 1–2 小时；重新打开时恢复原会话，保留历史记录。
- 新增本地计划工作区，支持搜索、筛选、逐任务预览、验收标准阅读和执行前确认。

### 体验优化

- 计划总览采用列表与详情分栏，预览一次展示一项任务，并保留任务、标签及阅读位置；字体保持一致，行距与段距更紧凑。
- 改善 issue 详情的工作区、执行信息和操作布局，恢复样式一致性，并适配手机与键盘操作。
- 收紧任务工具栏，用图标和提示承载次要入口，减少窄屏换行与操作拥挤。
- 执行机注册与编辑保留手填目录，自动检测只补齐空值；检测失败时仍可手动填写并提交。

### 问题修复

- 修复 tmux 启动环境参数位置、深层工作区 socket 路径及测试目录误认父仓库的问题。
- 自动准备与锁文件一致的依赖，准备失败保留工作区并提供恢复依据，避免将环境问题误报为业务测试失败。
- 暂停和验收失败显示真实的停止阶段、原因与下一步，完整诊断保留实际失败输出和省略标记。
- 终端与对话输入核对所属工作区、会话及执行轮次，避免输入进入其他任务。
- 模块记忆更新使用独立超时预算，并保留失败诊断，便于后续恢复。
- 删除已导入的 issue 时保留计划发布身份，防止重新读取计划后重复创建同一批任务。
- 计划预览固定打开时的版本，源文件变化后需重新核对；请求结果未知时跨刷新仍重试原请求。
- API 收到不完整或无效的 JSON 响应时明确报错，避免界面将请求误判为成功。

### 其他变更

- 发布流程改为先提交与推送代码、标记不可变 tag，再通过 SSH 在部署主机拉取、构建并原子发布，保留备份、回滚与健康检查。
- 聊天会话休眠保护运行中、有人连接、待答复和未发送草稿的会话；无法确认状态时保留运行资源。
- 本次升级包含模块工作区、模型设置和本地计划的数据库迁移；升级前应保留数据库与配置备份。模块工作区执行依赖 Linux。

<h3 id="en-v2.6.0">New Features</h3>

- Run different modules concurrently in dedicated Git worktrees while keeping tasks within each module sequential and respecting the project concurrency limit.
- Select models and reasoning levels for issues and conversations, with separate states for selected, pending, and session-confirmed settings.
- Hibernate idle chat sessions automatically after two hours by default, configurable from one to two hours, and resume the original session with its history when reopened.
- Add a local-plan workspace with search, filters, per-task previews, acceptance criteria, and confirmation before execution.

### Improvements

- Split the plan workspace into a list and details, preview one task at a time, and preserve task, tab, and reading positions. Keep the existing typography while tightening line and paragraph spacing.
- Improve workspace, execution information, and action layouts in issue details, restoring consistent styling and supporting mobile and keyboard use.
- Compact the task toolbar with icons and tooltips for secondary actions, reducing wrapping and crowding on narrow screens.
- Preserve manually entered executor directories and fill only empty fields through detection. Allow manual entry and submission when detection fails.

### Bug Fixes

- Fix tmux startup environment argument placement, socket paths in deep workspaces, and test directories incorrectly discovering a parent repository.
- Prepare dependencies according to the lockfile, preserve workspaces and recovery evidence on preparation failure, and distinguish environment problems from business test failures.
- Show the actual stopped stage, reason, and next action for pauses and validation failures, retaining real failure output and truncation indicators in complete diagnostics.
- Check workspace, session, and execution-attempt ownership before sending terminal or conversation input to avoid targeting another task.
- Use a dedicated timeout for module memory updates and retain failure diagnostics for recovery.
- Preserve plan publication identity when deleting imported issues so rediscovering the plan cannot recreate the same batch.
- Keep plan previews bound to the opened version and require review after source changes. Retry the original request across refreshes when its result is uncertain.
- Report incomplete or invalid JSON API responses explicitly instead of treating the request as successful.

### Chores

- Commit and push release code, create an immutable tag, then fetch, build, and atomically deploy on the deployment host through SSH, retaining backups, rollback, and health checks.
- Protect running, connected, awaiting-response, and unsent-draft chat sessions from hibernation. Retain resources when session state cannot be confirmed.
- This upgrade includes database migrations for module workspaces, model settings, and local plans. Keep database and configuration backups before upgrading. Module workspace execution requires Linux.
