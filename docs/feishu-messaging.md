# 飞书消息沟通

完整管理员配置、同事使用与排障入口见[飞书使用指南](feishu.md)，登录身份规则见[同企业登录](feishu-colleague-login.md)。

在管理 → 飞书的消息区开启消息通道。通道复用已保存的 App ID / App Secret，开关独立于扫码登录；保存后即时生效，不需要重启。登录配置本身不会替原本关闭的消息通道打开开关。

## 飞书开放平台设置

1. 为同一个企业自建应用启用机器人。
2. 在事件与回调中选择长连接接收事件，订阅 `im.message.receive_v1`。
3. 申请机器人私聊消息读取权限 `im:message.p2p_msg:readonly` 和发送权限 `im:message:send_as_bot`。
4. 发布应用版本，并把需要使用的同事加入应用可用范围。
5. 回到管理页保存消息开关；观察连接状态。管理员绑定自己的飞书账号后，可点击“给我发送测试消息”。测试接口只使用当前登录管理员的绑定，不接受指定其他收件人。

参考：[飞书发送消息 API](https://open.feishu.cn/document/server-docs/im-v1/message/create)。连接成功表示长连接建立；发送权限和应用可用范围还需要通过测试消息验证。

## 同事使用

- 先用飞书登录 PandaDOS，建立本人账号绑定。
- 私聊机器人发送“项目”或 `projects`，查看自己可访问的项目。
- 发送 `#项目ID` 选择项目，然后直接提问；也可以发送 `#项目ID 问题`。仅有一个可访问项目时自动选择。
- 项目同名时使用 ID；项目名含空格也支持精确匹配。
- 项目选择按用户隔离，当前只保存在内存；手动重连、替换凭据或服务重启后重新选择（SDK 自动断线重连保留选择）。每次提问交给项目 PM，尚未保存飞书问答历史。
- 现有项目订阅继续发送进度、完成、阻塞和审批通知；项目所有者自动订阅，其他成员按本人订阅接收。

当前接收机器人私聊中的文本。图片、文件和群消息不进入项目 PM。项目范围遵循管理员、属主或项目成员权限，且只列出活跃项目。处理前和回复前重新校验绑定与权限，延迟通知发送前同样校验。

## 运行边界

- 消息 ID 使用有界、10 分钟的进程内缓存去重；服务重启后不承诺跨进程去重。
- 保存应用凭据立即使旧连接失效，通知缓存随连接注销清理；关闭消息不影响扫码登录。
- 管理 API 返回连接状态和最近收发时间，只暴露固定错误码，不返回凭据或 SDK 原始错误。
