# Issue 执行与完成策略

新建普通任务默认直接执行：准备分支和实施基线 → 连续实施 → 同轮完成报告 → 系统必要验证 → 完成。存量任务保持原计划；人工评审、设计工作流与显式选择规划的任务保留规划流程。内部实现步骤不自动拆成调度任务，复杂度判断不额外调用模型。

| 事实 | 状态与动作 |
| --- | --- |
| 已满足原始目标和确认的验收条件 | 必要门禁通过后 done |
| 还有可以自行实施/修复的工作 | implementing |
| 缺少影响方向的信息或用户决策 | 等待澄清；超时仅提醒 |
| 目标内有无法自行解除的外部障碍 | blocked，写明解除动作 |
| 执行器、协议或重试预算异常 | paused，保留阶段和恢复上下文 |
| 可选优化、范围外部署或后续观察 | optionalFollowUps，不影响完成 |
| 开发已完成，但自动推送失败或超时 | done，保留未推送标记与通知；无需用户解锁 |

直执行报告与 `ISSUE_READY:<issueId>:<implementation-eventId>` 同轮返回；系统拒绝旧轮次与其他任务的信号。`NEED_PLAN` 使用同样的绑定升级规划。报告缺失先补报一次，仍失败暂停；恢复沿用工作现场。普通任务不以生产发布为完成条件；明确要求“发布并测试”的任务仍须满足发布验收。

验证命令由控制器生成，项目显式配置优先。文档做差异检查，局部代码优先相邻/模块测试，公共接口、迁移、依赖等执行完整门禁。通过结果按执行位置、文件内容（包括未提交与未跟踪文件）、命令、配置/锁文件、环境与运行时版本识别；身份变化重新验证。依赖目录额外纳入元数据。自定义命令、过大输入、符号链接或身份计算失败不缓存。运行器异常是 error/paused，不是 skipped。

技能有 auto/manual/disabled 三种策略，任务覆盖模块，模块覆盖项目；未显式配置的 superpowers 默认 manual。普通任务不启动重流程。策略在下次实际启动会话生效，不改变运行中进程；会话保存来源、版本、内容摘要及限制，实际调用与读取分别记录。新增安装内容在下一次任务发现时纳入清单，不自动安装热门技能。

本次验证的本机版本为 Claude 2.1.270、Codex 0.154.0。Claude 使用 skillOverrides 和 enabledPlugins：普通技能支持可见性控制，插件只能整体开关，混合策略无法隐藏插件内单个技能。Codex 使用 skills.config 的路径禁用；manual 技能需在启动前通过任务覆盖启用。托管或动态发现的技能可能不在本地快照内，不能宣称完全隔离。其他执行机需以其 CLI 支持情况验证。

参考：[Claude 技能可见性](https://code.claude.com/docs/en/skills#override-skill-visibility-from-settings)、[Codex 技能配置](https://learn.chatgpt.com/docs/build-skills)。策略通过会话启动参数及独立脚本应用，不修改用户全局插件缓存或共享技能文件。

执行详情提供路径、暂停原因、注入/补报/验证/复用/实际技能调用事件及耗时，沿用既有 token/费用采集；不额外请求模型生成运行摘要。事件数不等于模型请求数，短样本不能证明固定百分比的成本下降。

## 成本复核

`bun scripts/issue-execution-report.ts <SQLite库路径> [天数]` 只读输出按执行方式、代理、验证范围分组的创建 cohort：完成率、已采集完成任务平均 token、请求数、注入/催办/验证复用/补报次数和完成耗时。未采集用量不当作零成本；Codex 输入已含缓存，避免重复相加。验证范围只作影响代理指标，不自动认定任务复杂度。

持久化用量当前没有可靠模型归属，因此模型字段明确为 unknown；详情页仍可查看会话实际模型。跨模型的效果排序、误受阻率和非必要澄清率需要运行样本与原验收复核，不用推测值填充。
