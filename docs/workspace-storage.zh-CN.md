# 工作区存储生命周期

[English](workspace-storage.md)

服务在项目绑定的执行机上运行持久化回收器。PM 通过 `workspace_resources` 查看记录，并按本项目的回收记录 ID 请求重新检查。入口只接受固定动作和记录 ID，不接受命令、路径或强制删除。

集成候选只有在成果已合入、issue 已完成、执行停止且工作区已释放后才可回收。回收器检查仓库身份、Git 登记、HEAD、冲突、未确认操作和进程引用；归档并校验独有诊断与运行数据，再通过普通的 [`git worktree remove`](https://git-scm.com/docs/git-worktree) 移除候选。存在改动、未知写者或不确定结果时保留现场和原因，不强制移除。

空闲模块保留源码、提交、进度和运行数据库，可回收被忽略的依赖安装、构建产物和已确认结束轮次的缓存。环境转冷后，下一条 issue 在原模块 worktree 上按锁文件重新准备依赖。仍被占用或暂停的执行继续受保护。自动提交排除运行会话、临时状态与根依赖安装；旧运行文件解除索引跟踪时保留磁盘内容和 Git 历史。

归档与执行机回执位于 `<executor.workspace_root>/.panda-archives/`，不依附将被删除的候选目录。已核验的忽略资源先通过同文件系统原子移动转入专属回收暂存区；大归档校验和大目录删除在共享仓库 Git 锁之外完成。跨文件系统、资源变化或删除不完整会保留审计记录，不回退到不受约束的删除。

控制器在 SQLite 记录所有权、保留原因及归档和删除结果；释放与候选回收意图在同一事务提交。启动和周期对账补齐遗漏意图，并将执行机回执与实际路径、Git 登记核对。不确定操作继续保留占用，超时或控制进程退出不授权第二个写者。停机等待在途回收结束后才关闭执行机和数据库。

## 容量设置

| 环境变量 | 默认值 |
| --- | --- |
| `PANDA_WORKSPACE_MIN_FREE_BYTES` | 2147483648（2 GiB） |
| `PANDA_WORKSPACE_CACHE_MAX_BYTES` | 2147483648（2 GiB） |
| `PANDA_WORKSPACE_ARCHIVE_MAX_BYTES` | 4294967296（4 GiB） |
| `PANDA_WORKSPACE_IDLE_MS` | 21600000（6 小时） |
| `PANDA_WORKSPACE_ARCHIVE_RETENTION_MS` | 604800000（7 天） |

参数为以字节或毫秒表示的非负整数；嵌入装配也可通过 `ServerOptions.workspaceReclamationPolicy` 覆盖。

缓存预算是软回收水位：超过预算会立即登记符合条件的空闲环境，由后台提前回收，不必等满空闲时长；执行机真实剩余空间充足时，不阻止其他模块的新 issue 启动。活动、含未提交修改或不可检查现场的缓存继续保留，其受保护状态不能阻断整台执行机。空间检查发生在执行机真实的工作区、候选/安装与归档文件系统上。空间不足延后新任务、候选创建和依赖安装，不消耗环境修复次数。回收使用独立的小额写入余量，因此低于新任务启动水位时仍能释放已停止缓存。

已完成归档按保留期轮转；容量压力可提前轮转旧的已完成归档。通过 `workspace_resources` 的 `pin`、`unpin` 固定或取消固定本项目归档。固定、未完成及未知归档不会被清理；删除结果未确认期间不能声称固定成功。归档过大时保留原现场。上限按执行机累计，包含使用该执行机的其他项目；未知归档载荷计入占用，但回收器不删除。

PM 清单优先显示未完成记录，再显示完成历史，并提供稳定的保留原因。`recheck` 重新核验，不能绕过数据保留、容量或所有权约束。
