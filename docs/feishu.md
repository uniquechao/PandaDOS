# 飞书使用指南

PandaDOS 支持同企业飞书登录、账号绑定、机器人私聊项目问答、项目通知和审批卡片。管理员统一配置应用，同事使用各自的 PandaDOS 账号和项目权限。

## 功能一览

| 功能 | 使用方式 | 权限与边界 |
| --- | --- | --- |
| 同企业登录 | 在登录页使用飞书扫码 | 首次建号需开启自动建号并通过企业校验；创建普通用户 |
| 账号绑定 | 已登录用户通过飞书绑定入口关联本人身份 | 已有绑定账号保持原有身份，不按飞书姓名合并账号 |
| 项目问答 | 私聊机器人选项目后提问 | 项目 PM 应答，只访问本人有权限的活跃项目 |
| 项目通知 | 按项目或 issue 订阅接收动态 | 属主自动订阅；其他成员按本人订阅接收，订阅不替代项目权限 |
| 审批卡片 | 从收到的卡片选择批准、拒绝或菜单选项 | 校验绑定身份、操作权限和请求状态；已处理请求不能重复执行 |
| 管理与验证 | 管理 → 飞书（`#/admin/feishu`） | 仅管理员可配置、重连和向本人发送测试消息 |

## 管理员首次配置

### 1. 配置同一个企业自建应用

在飞书开放平台准备企业自建应用，取得 App ID 和 App Secret。为应用启用机器人，将同事加入应用可用范围，并发布应用版本。登录与消息共用这一份应用凭据。

登录需要应用能获取用户身份；开启同企业自动建号还需要企业信息查询权限 `tenant:tenant:readonly`。机器人私聊需要：

- 私聊消息读取权限：`im:message.p2p_msg:readonly`。
- 机器人发送消息权限：`im:message:send_as_bot`。
- 在事件订阅中选择长连接模式，订阅 `im.message.receive_v1`。

应用权限、可用范围或机器人能力发生变化后，按飞书平台要求完成发布。登录使用浏览器 OAuth 回调，消息使用服务端长连接，两者是不同的接入链路。

### 2. 保存并验证登录配置

打开 PandaDOS 的「管理 → 飞书」：

1. 填写 App ID、App Secret 和公开站点地址。站点地址只填协议、域名和可选端口，例如 `https://panda.example.com`，不要包含页面路径。
2. 将页面显示的完整回调地址加入飞书应用重定向地址白名单，例如 `https://panda.example.com/api/feishu/oauth/callback`。
3. 按需开启飞书登录和同企业自动建号，点击验证凭据与企业。
4. 确认结果后保存配置。验证针对当前表单，不会替你保存。

企业验证成功可以证明凭据与企业查询可用，但不能证明应用已经发布、同事在可用范围内，或回调白名单填写正确。详细说明见[同企业登录与绑定](feishu-colleague-login.md)。

### 3. 开启消息并验证收发

1. 在同页的「飞书私聊消息」区域开启开关，点击「保存消息配置」。只勾选而不保存不会建立连接。
2. 等待状态变为「已连接」。配置保存后即时生效，不需要重启服务。
3. 当前管理员绑定本人飞书账号后，点击「给我发送测试消息」，确认本人收到消息。
4. 用飞书私聊机器人发送“项目”，确认收到项目列表；管理页的最近收发时间应随之更新。

连接状态只反映长连接状态。发送成功还取决于机器人发送权限和应用可用范围，因此需要分别检查连接、发送和接收。测试按钮只向当前登录管理员的绑定账号发送，不支持填写其他收件人。详细说明见[消息配置与实现](feishu-messaging.md)。

## 同事日常使用

先用飞书登录 PandaDOS。开启自动建号时，首次登录会核验企业并建立普通账号；同企业身份不会自动获得别人的项目权限。需要协作时，由有管理权限的用户将同事加入相应项目。

以下 ID `123` 仅为示例，应替换为机器人列出的实际项目 ID：

| 私聊内容 | 结果 |
| --- | --- |
| `项目`、`projects`、`帮助`、`help` | 列出当前账号可访问的活跃项目 |
| `#123` | 选择项目并收到确认 |
| `#123 现在进度怎么样？` | 选择项目并向该项目 PM 提问 |
| `现在有什么阻塞？` | 向已选项目 PM 提问；只有一个可访问项目时自动选择 |
| `#项目完整名称 问题` | 按完整名称定位项目；同名时改用 ID |

多项目且尚未选择时，机器人先返回项目列表。项目选择按用户隔离；不能通过输入其他人的项目 ID 绕过权限。普通成员只能访问自己拥有或作为成员加入的项目，管理员可访问活跃项目。

进度、完成、阻塞等消息根据订阅发送，待确认操作可以通过现有审批卡片处理。移出项目或更改飞书绑定后，后续回复及延迟通知会重新校验权限和当前绑定。

## 配置优先级与维护

- 管理页保存的登录配置整行覆盖部署环境的默认值。密钥留空保留同一应用的旧密钥；更换 App ID 必须重新提供密钥，显式清除后不会恢复环境变量中的旧密钥。
- 消息开关单独保存，独立于登录开关。关闭消息不影响扫码登录；关闭登录也不会自动关闭已启用的消息。
- 保存应用凭据会替换消息连接，点击「重新连接」也会重建连接；旧连接的待发送通知缓存随注销清理。
- `PANDA_FEISHU_APP_ID`、`PANDA_FEISHU_APP_SECRET`、`PANDA_PUBLIC_URL` 是未保存登录配置时的部署兜底。未保存消息开关时，只有部署提供了应用凭据且 `PANDA_FEISHU_CHANNEL` 不为 `off`，消息才默认开启；之后以管理页保存的开关为准。
- 测试和生产应分别确认本实例的开关与应用凭据。已有数据库开关时，仅修改环境变量不能代替关闭管理页中的消息开关。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 凭据验证失败 | 检查保存的 App ID、密钥及服务到飞书的网络；换应用后重新填写密钥 |
| 凭据通过、企业验证失败 | 检查 `tenant:tenant:readonly` 权限及应用发布状态 |
| 同事无法登录 | 检查回调白名单、应用可用范围、发布状态、自动建号开关和所属企业；配置刚变更时重新扫码 |
| 状态为未配置或未开启 | 先保存应用凭据，再独立保存消息开关 |
| 一直连接中、重连中或连接失败 | 检查飞书长连接设置、服务网络与应用凭据；修正后点击重新连接 |
| 已连接但测试发送失败 | 检查本人绑定、机器人能力、发送权限和应用可用范围 |
| 发给机器人却没有回复 | 确认发送的是私聊文本、已订阅接收事件，并观察最近收到消息时间；未绑定时先登录或绑定 |
| 看不到某个项目 | 确认项目活跃且账号是属主或成员；同企业身份不会自动共享项目 |
| 问答失败或无法查询进度 | 检查 PandaDOS 的驱动大模型配置及该项目执行机状态；飞书连接成功不等于 PM 或执行机可用 |
| 没收到项目通知 | 检查本人订阅、项目权限、飞书绑定及最近发送错误 |

## 当前限制

- 仅处理机器人私聊文本；群消息、图片和文件不会进入项目 PM。
- 私聊是项目 PM 的问答入口，尚未持久化飞书问答历史。记住选中项目不等于保存完整聊天上下文。
- 项目选择保存在当前通道实例内存中；手动重连、替换凭据或服务重启后需重新选择。SDK 的自动断线重连不重建该选择状态。
- 消息 ID 去重为有容量上限的进程内缓存，有效期 10 分钟，不承诺跨重启去重。
- 本文描述功能和配置方式，不代表任一部署已启用；以该实例管理页显示的状态为准。
