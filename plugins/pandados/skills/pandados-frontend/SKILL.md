# PandaDOS 前端

将 PandaDOS 识别为温暖、克制的 AI 编排工作台：暖白画布、琥珀黄强调、细线图标与轻盈层次，而非炫技式科技界面。

**REQUIRED SUB-SKILL:** 使用 `pandados-i18n` 处理所有用户可见文案、状态、错误、时间、数字与无障碍名称。

## 必经流程

1. 先完整阅读 [视觉规范](references/visual-system.md)，并查看 `assets/visual-references/` 的四张原始图；再检查现有页面、组件和样式实现。
2. 保持既有产品功能、路由、信息架构、字段含义与用户提供的原始文本不变。需求未明确授权时，不重命名、重排或删除导航和内容。
3. 先复用或补齐 Token 与组件变体，再组合页面；按视觉规范实现状态、交互、键盘焦点、窄屏布局和减弱动效。
4. 使用实际状态（加载、空、错误、禁用、完成）验证视觉结果；确认改动没有破坏已有功能和信息层级。

## 资源导航

- [视觉规范](references/visual-system.md)：完整 Token、组件、动效、可访问性与 Do/Don't；每次改动必读。
- `assets/visual-references/01-visual-system.png` 至 `04-layout-exploration.png`：不可替代的原始视觉参考，用于比对整体氛围、密度和组件细节。

## 实施准则

- 将黄色只用于主要操作、当前态、进度和关键反馈；保持内容区以暖白、浅米色和细边框为主。
- 让一个页面只有清晰的视觉主次；优先保留留白、可读文本和稳定的信息扫描路径。
- 组件的默认、悬停、按下、禁用、成功、警告、错误与焦点状态必须同一套 Token 化规则。
- 动效只用于解释状态或空间变化；尊重 `prefers-reduced-motion`，不得用动效掩盖加载或错误。

## 交付检查

- 对照四张图检查颜色、圆角、边框、阴影、图标线宽、间距与终端横幅。
- 检查窄屏可读性、键盘操作、焦点可见性和文本对比度。
- 若项目有前端构建或测试命令，运行与改动相称的验证，并报告结果。
